# Selah

A zoomable Bible for iPhone, iPad and Android. You zoom from the whole canon down to a book, a chapter, a verse and the original Hebrew or Greek word. It also has a 3D cross-reference galaxy, the Descent scroll, read-aloud narration and a daily or weekly reading plan.

The app is a [Capacitor](https://capacitorjs.com) shell around the same page as the web prototype. Everything ships inside the app, so it works offline: the KJV text, cross-references, the Hebrew and Greek data, narration audio, fonts and Three.js.

## Layout

| Path | What it is |
| --- | --- |
| `web/` | The app page (`index.html`) and its data: `bible.json`, `xref.json`, `lexicon.json`, `orig/`, `audio/` |
| `native/` | `native.js` connects the page to native features: reading-plan reminders, haptics and sharing. `native.css` handles safe areas. |
| `scripts/build-web.mjs` | Builds `www/` from `web/` and bundles fonts and Three.js locally |
| `ios/`, `android/` | Native projects generated by Capacitor |
| `assets/` | Source icon and splash images. Regenerate them with `npx capacitor-assets generate`. |

## Build

You need Node 22. For iOS you need a Mac with Xcode 16 or later. For Android you need Android Studio.

```sh
npm ci
npm run ios       # build www/, sync, open Xcode
npm run android   # build www/, sync, open Android Studio
npm run serve     # try the bundled app in a browser at http://localhost:8080
```

Every push builds an Android debug APK and an unsigned iOS simulator build on GitHub Actions (`.github/workflows/build.yml`). You can download the APK from the run's artifacts.

## Publishing to the App Store

1. Join the Apple Developer Program ($99 a year).
2. In Xcode, open the App target, go to Signing & Capabilities, and pick your team. The bundle id is `com.patrickil07.selah`. If you change it, change `appId` in `capacitor.config.json` to match.
3. Choose Product, then Archive, then Distribute App, then App Store Connect. Test the build on your iPhone through TestFlight.
4. In App Store Connect, add screenshots, a description and a privacy policy URL, then submit for review.

## Data sources

- **Bible text:** King James Version, plus the World English Bible, Berean Standard Bible and American Standard Version (all public domain).
- **Cross-references:** OpenBible.info, CC BY.
- **Hebrew and Greek:** STEPBible-Data TAHOT, TAGNT, TBESH and TBESG from Tyndale House, Cambridge, CC BY 4.0.
- **Narration:** the Kokoro-82M open model, Apache 2.0. Audio is pre-rendered for sample chapters only.
- **Timeline:** Theographic Bible Metadata by Robert Rouse, CC BY-SA 4.0. Dates follow Ussher's chronology. `web/timeline.json` is a derived work under the same licence.
- **Map:** Natural Earth land outlines (public domain), via world-atlas.
- **Search by meaning:** the potion-base-8M static embedding model by MinishLab, MIT (see `web/sem/LICENSE.txt`), taken from the npm package counterparts-model-potion. `scripts/data/prep_semantic.py` builds the verse index.
- **Spoken Hebrew and Greek words:** rendered with the same Kokoro voice from espeak-ng pronunciations (modern Israeli Hebrew, reconstructed ancient Greek) by `scripts/narration/words.py`.

## Whole-Bible narration

`scripts/narration/chapters.py` renders one MP3 per chapter plus verse timings. `.github/workflows/narration.yml` runs it on GitHub Actions in 40 parallel jobs whenever the `narration` branch is pushed (or by hand from the Actions tab once it is on `main`). Each book becomes a release tagged `{voice}-{book}`, and the timings are committed to `timings/{voice}.json` on the `narration` branch. The app streams any chapter that has timings and falls back to device voices for the rest.

## Windows and the Microsoft Store

`windows/` wraps the same app (`www/`) in Electron. CI builds two files on a Windows runner and checks the app opens:
an `.appx` for the Microsoft Store (Microsoft signs it when it is published) and a `Selah-Setup` installer for direct testing.

The Store product is **Selah Bible** (Store ID 9N120SPF1JMG). Its Partner Center *Product identity* is in
`windows/package.json` (`build.appx`), so every build's `.appx` can be uploaded to a Store submission.
Raise `version` there for each new submission.

Run locally on Windows: `npm ci && npm run build`, then in `windows/`: `npm ci && npm start`.
